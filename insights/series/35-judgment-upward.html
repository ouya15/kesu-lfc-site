35 判断力上浮：从流程引擎到「事实与门禁」

2026-09-13·连载

前情：23《原子能力》给了零件，24《三件套》给了封装，34《编排层》给出了第一版链路设想。这一篇是 34 的续章，也是它的自我推翻——那条链路的详细设计写出来的当晚，它长成了我最不想要的样子。

一句话：凡是"必须为真才能继续"的，机器门禁，不许自报；凡是"接下来怎么办"的，绝不写死，留给 Agent。 引擎管事实与门禁，Agent 管路径与善后。

引子：一句话

34 号文写完的当晚，我把"补材料"那条五段链路推进成了可实施的详细设计。

自认为很完整：两张状态表（run 与 step）、七个状态、一条串行执行链、八个路由（还能续跑、取消、单步重试）、一枚全局锁。每一步谁执行、失败怎么退避、服务重启后怎么续——全都写死了。

设计发出去评审。回来的追问只有一句话：

"Agent 在哪？"

我盯着自己写的东西重新过了一遍，承认：这里面没有 Agent。有一个调度器，一个状态机，一张异常处置表——而 Agent 只剩两个动作：点火，和看报错。

这份设计后来被我自己推翻重写。这篇写的就是推翻的过程，和推翻之后还剩下什么。

1. 病根：把判断力写进了流程

先说清那份设计在防什么——它防的东西是真实的。

之前的半年里，"缺材料"是静默发生的：某批字幕丢了要等对账才浮出水面；跨会话的交接依赖上下文记忆；夜里的批跑靠一个人盯日志。所以我给编排层定的第一纪律是"不许静默"：状态进库、异常落表、断点可续。

方向没错，但手段错了。我把"防静默"翻译成了"把一切写死"：五段链的顺序写进代码，异常处置写成状态机分支，连"什么时候重试、重试几次"也钉进了引擎。

写死的代价，被一门门真实的课当场敲了出来：

  • 有一门课，一页图表都没有（纯推导讲）——按写死的链，"图面层缺失"永远补不上，流程永远卡在失败态；
  • 有一门课，官方不发讲义——"完整档"对它永远不可达，可状态机只认"达标/不达标"两值；
  • 有一门课，没有双语轨——补全链的入口条件就得为它特判。

每门课的形状都不一样，而我的设计假设了它们一个样。把判断写进代码的那一刻，代码就拥有了对现实的最终解释权——可现实里，每一门新课都在改写法典。

这不是编排的错，是时代的错位：状态机、重试策略、异常分支表——这些是"代码是唯一执行者"的年代留下来的补丁。那时的执行者不会思考，思考只能预先写成分支。现在执行者会思考了，你却把它的脑子摘掉、用表格代替——这不是工程，是买椟还珠。

2. 判据：事实与门禁，路径与善后

推翻之后，第一个问题是：那什么东西该留在引擎里？

找到的判据线很短：

凡是"必须为真才能继续"的 → 机器可判的门禁，不许 Agent 自报；凡是"接下来怎么办"的 → 绝不写死，留给 Agent。

前者是事实：材料在不在、件数对不对、哈希合不合、动作幂等不幂等。它们必须由机器给出——因为 Agent 会（也必然会）把"我觉得好了"说成"好了"。门禁是自治的门票：没有硬验收，放开手就是放任。

后者是判断：这门课该补到哪一档、这条链先走哪步、一个卡住的作业是等还是弃、这一跤值不值得再试一次。它们写不进代码，因为写下来的那天就开始过期。

分工落下来是四个角色：

  • Agent——编排者、善后者、升级者；
  • 能力——哑执行器，幂等，只回答"做完没有"；
  • 门禁——验收判据加证据，唯一的"为真"裁决者；
  • 台账——事件与清单，"现在到哪了"是一次现扫，不是一个状态机。

于是整条流水线，收敛成六行：


loop:
  st     = inspect(course)    # 事实：材料世界里现在有什么
  need   = plan(st)           # 差集：缺什么（纯函数，机器可判）
  action = agent.decide(need) # 判断：怎么补（Agent 的角色所在）
  result = agent.act(action)  # 动作：调用能力；多级组合 = 顺序调工具
  assert verify(result)       # 门禁：必须为真，不许自报

读懂这六行，就读懂了我对"agent 时代该怎么编排"的全部回答：引擎只提供事实与门禁，路径与善后归 Agent。 那张五段链没有消失——它降级成了文档里的一段"默认路径"，成了 Agent 手里的参考，而不是它头上的规矩。

3. 减法结算

重写完的版本：

  • 删掉：两张状态表、七个状态、八个路由、一枚全局锁，以及整套"续跑/取消/重试"的生命周期（7 态 → 0 态；8 路由 → 2；2 表 → 0）；
  • 留下：两个只读端点——一个给差集（缺什么），一个给门禁（为真没有）；一段 SOP 文档（默认路径 + 偏离处置表）；一组能力调用（幂等工具）；
  • 新增：一个不带 LLM 的薄脚本——按默认路径机械循环，只在遇到偏差时把 Agent 叫醒。

留与删的分界，就是那条判据线本身。落收的原子性（半截文件永不落位）、对账（件数、哈希零差）、审计（谁在哪个凌晨动了什么）——一步没让，因为它们正是"必须为真"的东西。

重的是脑子，薄的是引擎。

4. Agent 在 DAG 里，还是 DAG 在 Agent 手里

推翻过程中想清的另一个问题，是两种形态的选择。

Agent 在 DAG 里：图是执行主体，某些节点"调用一个 Agent"。适合链固定、判断点已知、需要可重放的场景——"每一步都说得清"的合规式流程是它的主场。

DAG 在 Agent 手里：Agent 是执行主体，图降级为它手里的 SOP。适合任务异质、形态漂移的场景——每门课长一个样，就是这种。

我们选了后者，但保留一个逃生舱：机械路径。夜间批跑不需要一个每一步都在思考的 Agent——薄脚本按默认路径直跑"差集 → 动作 → 门禁"，遇到偏差（要降档、要花钱、要动受保护目录、同因失败第二次）才升级叫醒。Agent 在环，但不是每一步都在环。

将来某条链真的稳定了（第二次、第三次手动走过同样形态），再把它"凝固"成 DAG——那时的 DAG 也只是对同一组事实与门禁的薄封装，不是一台新引擎。这正是 22《换乘触发器》和 34 各自讲过的那条纪律：滞后封装，别提前抽象。

5. 不能交给门禁的东西

这条线也划出了门禁的边界，写下来防止它膨胀。

门禁只处理"可断言的真"。还有一类问题长得像判断、其实是品味：这一档降到 T1 值不值得？这版材料的质量"够不够好"？为一个丢掉的零件值不值得花一晚上？——这些写不成谓词，也不该硬写成谓词。硬写的后果不是严谨，是假精确：把"我觉得可以"伪装成"系统判定通过"。

所以这套设计里刻意保留了一段"手动挡"：降档必须显式记录。系统不会替你说"这门课就配 T1"——它只把事实摆出来，让 Agent 或人签字。签字这两个字很重要：它意味着有人对它负责。

6. 实战观察（回填：第二域先跑完了）

材料线的首战（同一门课九讲全链）还在等一个窗口——但这套骨架的实战没有等：它先在第二个域跑完了。译制线（把一讲英文公开课做成中文配音版）从 pilot 走到"全量"落地只用了一个中午，而且没有为它改过一行引擎代码（只在剖面里加了一条接线）。按当初留给这一篇的三个问题，逐条回答。

一、六行循环够不够用？ 够，而且是原样够的。译制线的 plan 是"缺底稿/缺双语/缺配音版"的差集；decide 是评审后圈定"这一批补什么"（断点续跑、引擎插拔、三门禁）；act 是顺序调工具——合成、对齐、换轨三件事就是三次能力调用，多级链没有变成引擎里的链；verify 是门禁。全程没有出现一个"必须写进引擎的分支"。 实战里真正需要重新发明的不是循环，而是每个域的谓词与门禁：译制线的时长对账、截断率上限、ASR 回读覆盖率，都是这个域自己长出来的。循环是常数，谓词面是变量——这条当初没写进设计，现在补上。

二、门禁有没有拦住一次"我觉得好了"？ 拦了两次，一次比一次有意思。 第一次是材料线：verify 对首战课程报 0/9、rc=1——"材料齐了"的叙事在门禁面前破产；同一个门禁对一门已经齐了的课放行 PASS。它会拦，也会放，说明它测的是现实，不是情绪。 第二次更妙——被拦的恰是门禁工具自己。译制线验收时，verify 对一讲明明存在的产物报了"不存在"。一查：它缺了短名解析，文档里教的用法会误报。这就是"我觉得好了"的镜像版：工具也会撒谎。修完拿四个用例复验（已知好 PASS、已知坏如实 FAIL、不存在正确报错）才算过。 也要诚实记下它没拦住什么：那一讲的音质和翻译质量都不行——但那是模型能力问题，不是"自报成功"，正好落在上一节说的手动挡里：品味问题不写谓词，由人签字"先不管"。

三、遇到"长歪了的"时候，改道是不是真的比状态机报错快？ 快。译制线里"长歪的"不是课，是链上的产物，三个实例：

  • ASR 旁路对 55 分钟的整轨"单发喂"退化成了 79KB 的同一句循环——rc=0，看起来完全成功。写死的链会把它当成功继续往下跑，产出一个语义为零的底稿；在环的 Agent 当场改道：判"必须分窗"，列入待做，链条继续。
  • verify 的短名 bug——当场修、当场复验，全部发生在跑全量之前。
  • 评审人说"音质翻译先不管，看编排"——链条立刻从"调模型"改道到"补工程"，没有卡在质量态里等人拍板。

改道快的根因不是 Agent 聪明，是引擎薄：没有状态机需要"报错→翻译成人话→找到绕过它的路"，Agent 直接面对事实与门禁，改道只是换一个动作序列。

结语

按版本号算，这是一次"v0.1 被 v0.2 推翻"。但真正的版本号是那句话——设计里没有 Agent 的地方，就是设计里没有思考的地方。

材料线的首战仍在等窗口；但这份 v0.2 已经不缺实战——第二域（译制线）替它把三个问题都答了（见上节），34 号文的时间账与失败实录同批回填。这次回填还带来一个当初没敢写的结论：同一副骨架能原样搬去另一个域先跑，正是因为薄的是引擎、厚的是 SOP 与门禁——如果当初那台状态机活着，它根本搬不动。
