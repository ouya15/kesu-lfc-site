34 编排层：能力齐了之后

2026-09-13·连载

前情：17《别用 SSH 当 API》换了通道，22《换乘触发器》给出"何时换"，23《原子能力》讲了封装的第三级，24《三件套》拆了零件。这一篇写下一级的第一课：把零件串成流水线。以及它开工前先绊的那一跤。

一句话：能力层回答"单件事会不会做"，编排层回答"一串事怎么自己做完"；而编排器该不该存在，不由"想到了"决定，由"第几次使用"决定。

引子：一件不在盘上的零件

九讲课程视频躺在算力节点上。素材清了一半——视频在、英文字幕在，还缺两条声道：逐帧的版面，和图表页的读图层。

要把"缺材料 → 补材料 → 齐了开写笔记"做成一条流水线，本该是攒了半年的原子能力兑现的时刻：帧提取、帧 OCR、读图描述，每个零件都造过、跑过、全库 73 讲一次性批过——日志里最后一行还写着 ALL DONE: 73 new, 0 skipped, 0 failed。

于是先做审计：能力清单摆开，挨个点名。

点到"帧提取"，它没答到。

脚本不在盘上了。源侧没有，执行侧也没有。而它 24 小时前刚刚干完 73 讲的活。原地只剩下三样东西：一份日志、一段陈年崩溃的堆栈（堆栈里留着它当年的住址）、一条还在体检项里挂着名字的计划任务。

你要自动化一条线，第一个发现常常是：这条线上有一个零件已经丢了。

它大概率还能找回来（冲突处理时打过一个 6.1GB 的暂存包）。但这跤本身已经是编排层的第一课：能力不是造完就永远在的。文档会过期，日志才是不会失忆的物证；而"零件盘点"必须是流水线的第 0 步。

1. 什么时候才配拥有编排器

先说一个反直觉的次序问题。

这条流水线其实早就"造过"——只是造在人的脑子里：73 讲的批量加工，靠一条计划任务、一个人定时看一眼日志、以及最后手动把产物同步回本地。它跑通了七十三次，零失败；甚至有一条体检项专门盯着它的死活。

但它不能被委托、不能被重放、也不能在你睡着时自己决定"下一步该干嘛"。

那为什么当时不把它封装成编排器？因为当时的纪律是：第一次使用不封装。 第一次是探路——你还不完全知道链路长什么样、哪个环节会炸、失败要怎么退；这时候抽象的每一个接口都是猜的。等第二次真的要用它（换一门课、换一批素材、换一个人操作），链路已经被用脚投票定型了，封装才从"抽象税"变成"省税"。

这和 22《换乘触发器》是同一条纪律的两次现身：接缝税只对第二次收费。编排器不是提前抽象，是滞后封装——它的触发信号不是"我有一个好主意"，而是"我第二次手动跑完了同一串命令"。

这次就是第二次。

2. 编排层的形状：五段，和两条分工线

把"补材料"这件事拆开，其实是五段：

  • 发现——逐讲核对材料清单，输出"缺什么"。这一步的产物必须是机器可读的：不是"感觉这门课缺资料"，是"九讲里九讲缺版面层、九讲缺图表层"。
  • 补全——按缺口选能力、排链路。这里的链路是多级的：帧提取（采样、去重、抽帧）→ 帧 OCR（把画面变成字）→ 图面 VLM（把图表变成描述）。上一级的产物是下一级的输入，顺序错一步整个白跑。
  • 落收——产物在对面的机器上，要搬回来。听起来是杂活，其实是事故高发段：搬运失败往往静默（空文件、半截文件），所以落收也要走可校验通道（打包 + 哈希 + 单次取件），而不是"一堆小文件挨个拷"。
  • 验收——"齐了"要有判据：件数对得上、哈希对得上、随机抽几帧肉眼能看。验收不是仪式，它是把"我觉得补完了"变成"证据表明补完了"。
  • 交付——材料进入下一个环节（写笔记），流水线的责任到此为止。

两条分工线，和 21《事实归机器，语义归模型》是同一条：

  • 能力层保持哑执行器。"帧提取"只管把视频变成帧，它不知道也不关心自己在为哪门课服务、后面还有没有别的步骤。链路的顺序、失败的重试、下一步该谁——全部由编排层决定。能力层一旦开始"聪明"，它就开始耦合。（任务的依赖语义不该塞进执行器也是同一个道理：编排层可以换、可以重写，执行器越蠢活得越久。）
  • 编排器不碰语义。"材料齐没齐"是事实判断，可以自动化；"这一讲讲了什么、笔记怎么写"是语义判断，必须留给人的那一侧。流水线的终点是材料齐备线，不是"自动写完笔记"——越界一步，就变成了用摘要替代理解，整条笔记线的质量纪律（整讲进上下文、逐字溯源）会第一个崩。

3. 把"齐了吗"变成机器可判：档位

"材料齐全"如果不定义，就是一句感觉。给它分级，它就能进代码：

  • T0 可读：视频 + 字幕在 → 能开工，但瘸一条腿；
  • T1 三声道：再加版面层（逐帧文字）和图表层（图的描述）→ 笔记生产的完整材料线，这是自动化的目标档；
  • T2 完整：再加官方讲义。有的课永远到不了 T2（官网就不发讲义），所以 T2 的缺失不阻塞——但必须被明示，而不是悄悄缺席。

档位的意义：发现环节的判断、补全环节的选链、验收环节的签字，全都锚定在同一个定义上。三段的"齐"是同一个字，不会各说各话。

4. 代价与边界

  • 能力会腐烂（本篇开头那跤）：脚本会丢、路径会挪、依赖会升级。所以盘点必须是流水线的第 0 步，而且盘点失败不能静默——"缺一个零件"要以一等公民的身份终止流程，而不是在半夜空转。
  • 幂等是编排的前提：第 2 步跑到一半断了、第 3 步搬了一半，重跑必须安全。每个能力都"已存在→跳过、重入→覆盖"，否则流水线只能一次成——那就还是人肉。
  • 共享资源要排队：读图用的显存和另一条管线（翻译）是同一块卡。编排层要替所有链路统一看门，单个能力再谦让，也架不住两条链路同时起跑。
  • 状态进引擎，不进聊天：跑到第几段、哪段失败、什么时候重试——如果要靠翻会话记录确认，流水线就退回了手工作坊。状态放进能被查询的地方，"现在到哪了"是一次查询，不是一次考古。

5. 实战观察（回填：第二域先跑完了）

计划里等的是材料线的首战（同一门课九讲全链）——那个窗口还没到；但同一套骨架在第二个域先跑完了实战：译制线（把英文公开课做成中文配音版）。它替这篇草稿答了大部分问题，也顺手修正了一处措辞。以下按原计划的五问回填，对不上的地方如实注明。

① 时间账。 单讲全链约 6 分钟墙钟：合成占掉 299 秒（约八成），对齐、混音、换轨加起来一分钟出头。之前最悬的"多级链会不会越跑越贵"，答案落地了：贵的是能力本身（合成），不是编排——编排是零成本的那一层。 幂等改造之后，同一讲重跑 49 秒（79 段全部复用、一段没重合成）。这是"幂等是编排的前提"的定价：从"每次全量重来"到"只跑差的"，重入成本掉了一个数量级。

② 失败与重试实录。 最值钱的一次失败不是"炸了"，是"没炸"：ASR 旁路对 55 分钟整轨单发喂进去，输出成了 79KB 的同一句循环——rc=0，日志全绿，只有去看产物本身才发现语义为零。这篇开头说"零件盘点必须是流水线的第 0 步"；这里补上后半句：验收必须看产物本身，rc 和日志都不算数。 第二次是工具级：门禁脚本自己的短名解析缺失，误报"产物不存在"，当场修掉、四用例复验。重入干不干净？79/79 复用、0 重做——干净。

③ 对账数字。 译制线不做跨机落收（产物留在节点上，本地只取回一段样片），这一条用"门禁对账"替代：产物 md5 钉扎、时长与原片逐秒一致（3289.222 秒）、截断率 12.66%（上限 15%）、作业 54.4 秒跑完。哈希、时长、比率——三件都是机器可判的真。

④ 单讲 vs 全量的差别。 单讲跑通 ≠ 全量可跑，但差别比想的窄：真正拦住全量的不是"链更长"，是两块——资源排队（合成吃 CPU，要和别的线错峰）和代价模型（重跑便宜 ≠ 首次便宜）。所以全量的准备工作不是"把链加固"，是"把能力提速 + 把幂等做扎实"。

⑤ 审计链。 一次作业查询（提交时间、完成时间、结果 JSON）＋一份门禁回执＋一篇日志——三步之内能复述"谁在哪一步、留下了什么证据"。状态没进聊天，也没进状态机。

结语

【原候选钩子】编排层的完成标准，不是"跑通了"，而是"丢一个零件也能发现，跑挂一段能自己重来"。

译制线把这两句都验了：盘点（差集）是每次开工的默认动作，"丢"在被看见之前就拦下了；断点复用让"跑挂一段"的代价从六分钟降到四十九秒。

还有一个计划外的收获：这套骨架没有和任何一个域绑死。材料线的首战还没跑，第二域已经先跑完了（过程见 35 号文）。同一批事实与门禁、同一套能力调用语法，连"多级链"都只是 SOP 里的一张顺序清单。如果当初那条五段链真的写进了代码（35 号文记了那场自我推翻），这次搬家根本不会发生。
