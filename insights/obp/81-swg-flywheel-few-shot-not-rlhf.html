81 飞轮不是 RLHF——SWG 自改进的校准机制

2026-06-27·obp

日期：2026-06-27

背景

SWG（站点写作规范）有一套 Scorecard + 反模式表 + 样本库。每次用户修改文章后，AI 采集 before/after 样本写入规范，形成"越用越好"的飞轮。最初类比是 LoRA + RLHF。

问题

类比不准确，而且机制本身有隐患：

  • LoRA/RLHF 改不了：我们改不了模型权重，只能改 context window 里的内容。真正的机制是 few-shot prompting——Agent 读到样本，生成风格向样本方向偏移
  • 样本堆积 = 规则堆积：负面约束太多的后果是"正面表达就死了"。如果样本库无限增长，Agent 会变成逐条检查的模式，和干规则的问题一样

方案

飞轮重构为两级：

  • 画面库（主要读取对象）：3-4 个具体画面，每个画面 1-2 个代表性样本。Agent 写文章前读这些，校准"味道对不对"
  • 反模式表 + Scorecard（校准参考，不逐条检查）：用于自评，不作为写作时的主要参照

飞轮流程从"写入样本库"改为"提炼画面"。样本是原材料，画面是产物。不是无限堆积，是少而精。

结论

Agent 的行为校准靠 few-shot，不靠训练。few-shot 示例应该少而精（画面），多而碎（逐条 case）会让 Agent 机械匹配。规则越多的系统越容易杀死弹性——这和 Famous Chicken、负面约束的结论是同构的。
