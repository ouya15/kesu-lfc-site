工作室札记

103 一个出版社，多个编辑部——职责分离，而不是 session 分离

2026-07-30·obp

日期：2026-07-30

关联：中心文章 #106（lfc-studio CMS 系统）；簇内 #221（批量 merge 方法论）。

问题：全包太重

我的技术 insight 散落在不同仓库、不同 session。最早让一个 session 跑选稿到上线的全流程——太重：它得同时装着所有域的上下文，每次编辑都得先喂背景。

最初，我把"判断内容"和"执行发布"拆成物理分离的两个 session——编辑部（每域一个）和出版社（专职发布）。

实践观察：物理分离很少发生

实际跑下来，单独的编辑部 session 很少出现。日常工作基本都在出版社这一个 session 里完成——写内容、评审、脱敏、发布。编辑部角色只在很大的项目里才单独开 session，小稿子都是随手写、随手发。物理分离只在上下文重到无法文档化时才可能出现。

上下文：外化到文档里

如果上下文可以被外化，一个 session 也能搞定：

  • catalog.json 存元数据——哪篇什么状态、什么标签、归哪个专栏，不用记
  • ROADMAP/BACKLOG 存状态与纪律——做到哪、下一步是什么，不用记
  • columns/ 存策展——专栏怎么排、每篇的导读，不用记
  • 批注系统存评审意见——评了什么、改没改，不用记

核心是让信息可查。

那分离还剩什么价值：职责边界

物理 session 分离弱化了，但"判断内容"和"执行发布"这两件事的职责分离没有消失，它落在了权限和纪律上：

  • 谁有 catalog 的写权限、谁能 publish——只有出版社
  • 编辑部只写文章 md，其他一概不碰
